# WVP 2.8.0 授权灰度、enforce 与角色表 contract 操作手册

本文用于把 2.8.0 的用户、角色、部门、视频资源组、API Key、媒体票据与 Hook 身份认证从 `audit` 灰度到 `enforce`，最后在停机窗口删除 2.7.x 角色主表。它不是“执行一次 SQL 就升级”的说明；每个阶段都必须留下可复核证据。

迁移脚本和备份恢复命令见 [2.8.0 数据库迁移与核对手册](2.8.0-migration-runbook.md)。端点与视频对象的授权口径分别以 [HTTP 端点权限矩阵](../security/endpoint-permission-matrix.md) 和 [视频资源授权矩阵](../security/video-resource-authorization-matrix.md) 为准。

## 1. 不可变边界

- `expand` 与 `contract` 分开。expand 可以重复执行，不删除 2.7.x 表；contract 只能在停机窗口执行。
- contract 后，旧应用不能与新表名混跑，也不能直接回退旧二进制。回退必须先恢复 contract 前快照。
- `authorization.mode=disabled` 不得出现在生产环境。
- `audit` 只改变权限拒绝策略，不关闭身份认证、媒体 Hook 身份认证、下载票据或 WebSocket 票据。
- `REQUIRE_RESOURCE` 端点不允许以 `LEGACY_AUDIT` 进入 enforce。
- API Key 的功能权限和视频资源组只能缩小所属用户当下权限，不能扩大用户权限。
- ZLM/ABL Hook 必须先认证媒体节点，再消费播放票据；缺字段、未知节点、未知协议映射或校验异常都不能默认放行。
- contract 前必须关闭旧角色双写：`authorization.legacy-role-dual-write-enabled=false`。

## 2. 负责人和证据目录

上线前指定四个责任人，不能由同一个人同时执行和批准 contract：

| 角色 | 责任 |
|---|---|
| 发布负责人 | 应用配置、灰度、enforce 切换和应用回滚 |
| DBA | 快照、expand、核对、contract 和数据库恢复 |
| 视频业务负责人 | 完整业务周期、设备/通道/录像/推拉流验收 |
| 安全复核人 | 权限矩阵、拒绝审计、Hook、票据和 LEGACY 清零签字 |

为本次变更建立只读留档目录，至少保存：

- 发布版本、Git SHA、数据库类型和版本；
- contract 前后快照名称、校验值和恢复演练记录；
- 本文所有核对 SQL 的原始输出；
- Maven、前端测试、数据库契约测试和静态检查输出；
- audit/enforce 观察起止时间、拒绝原因汇总和例外审批；
- 配置脱敏副本。密钥只记录 Secret 版本或引用，不保存明文。

## 3. 固定执行顺序

不得跳步或并行执行相邻的数据结构阶段：

```text
数据库快照
→ expand schema
→ 部署双写兼容后端
→ 配置角色/部门/资源组/API Key scope
→ authorization.mode=audit
→ 收集一个完整业务周期
→ Hook 身份 audit
→ 前端票据双轨验证
→ 关闭长期 URL
→ readiness 全绿
→ authorization.mode=enforce
→ 观察并处理拒绝
→ 停用并清零 LEGACY API Key
→ contract 前快照与恢复复核
→ 停机 contract
→ 新版本只读 smoke
```

“完整业务周期”由业务负责人定义并签字，至少覆盖设备注册与离线恢复、目录订阅、实时播放、停止、云台、设备录像、云录像、快照、下载、推流、拉流、分享播放、JT1078（如启用）、日志查看和媒体节点重连。不能用固定的十分钟观察替代业务周期。

## 4. 阶段 A：快照与 expand

### 4.1 基线

先按迁移手册记录用户、旧角色、API Key、云录像、媒体节点和资源组数量。以下结果必须保存：

```sql
select count(*) as users from wvp_user;
select count(*) as legacy_roles from wvp_user_role;
select count(*) as api_keys from wvp_user_api_key;
select count(*) as cloud_records from wvp_cloud_record;
select count(*) as media_nodes from wvp_media_server;
```

完成一次真实的“从快照恢复到隔离库”演练。只证明备份命令成功不算恢复可用。

### 4.2 执行 expand

MySQL：

```bash
mysql --default-character-set=utf8mb4 --show-warnings \
  -h DB_HOST -P DB_PORT -u DB_USER -p DB_NAME \
  < 数据库/2.8.0/更新-mysql-2.8.0.sql
```

PostgreSQL：

```bash
psql --set=ON_ERROR_STOP=1 \
  --host=DB_HOST --port=DB_PORT --username=DB_USER --dbname=DB_NAME \
  --file=数据库/2.8.0/更新-postgresql-2.8.0.sql
```

KingbaseES：

```bash
ksql --set=ON_ERROR_STOP=1 \
  --host=DB_HOST --port=DB_PORT --username=DB_USER --dbname=DB_NAME \
  --file=数据库/2.8.0/更新-kingbase-2.8.0.sql
```

同一 expand 脚本再执行一次，第二次也必须成功。随后执行迁移手册中的完整核对。任一数量不一致、孤儿关系、闭包缺失或索引缺失时停止发布；此时仍允许恢复快照并回退旧应用。

## 5. 阶段 B：双写兼容和授权配置

### 5.1 audit 配置基线

配置含义如下，Secret 值必须由部署环境注入：

```yaml
authorization:
  mode: audit
  allow-url-token-compatibility: false
  legacy-api-key-enabled: false
  legacy-api-key-sunset: 2026-10-01T00:00:00Z
  legacy-role-dual-write-enabled: true
  api-key-pepper: ${API_KEY_PEPPER}
  media:
    legacy-response-enabled: false
    hook-secret-pepper: ${MEDIA_HOOK_SECRET_PEPPER}
    # 没有 ABL 节点时保持空映射。
    abl-schema-by-network-type: {}
```

存在 ABL 节点时，应根据供应商文档和完整业务周期中实际收到的 `networkType`，把整数值显式映射到 `flv`、`ws-flv`、`hls`、`webrtc`、`rtsp` 或 `rtmp`；禁止照抄其他环境的数字或猜测默认协议。

`API_KEY_PEPPER` 和 `MEDIA_HOOK_SECRET_PEPPER` 至少 32 字节，分别管理，不得复用。修改 pepper 会使已有摘要无法验证，必须走受控轮换流程。

### 5.2 配置顺序

1. 建立部门树，仅用于用户数据范围；部门不代表摄像头归属。
2. 建立角色和菜单/功能权限。
3. 建立视频资源组及闭包关系，把设备、通道、推拉流、JT1078 和录像来源放入资源组。
4. 给角色设置 `ALL`、`CUSTOM` 或 `NONE` 视频范围；`CUSTOM` 必须绑定资源组。
5. 给用户分配角色并检查 token version 已失效刷新。
6. 通过管理接口新建或轮换 API Key，只保存一次返回的明文；数据库只能持有 hash、前缀和末四位。
7. 为 API Key 配置权限和资源组子集，确认没有超出所属用户当前范围。
8. 为每个媒体节点轮换 Hook 密钥，并确认节点配置已同步。

### 5.3 双写核对

audit 阶段保持 `legacy-role-dual-write-enabled=true`。新建、修改、删除一个测试角色后，检查新旧角色模型一致；生产角色不要为测试而随意修改。

```sql
select count(*)
  from wvp_user u
 where u.role_id is not null
   and not exists (
       select 1
         from wvp_user_role_rel urr
        where urr.user_id = u.id
          and urr.role_id = u.role_id
   );
```

期望值：`0`。非零时停止灰度，不进入 enforce。

## 6. 阶段 C：audit 观察和 readiness

### 6.1 端点与资源矩阵

```bash
mvn -Dtest=EndpointClassificationTest,AuthorizationEnforceReadinessTest test
```

该测试验证仓库配置、H2 数据契约、端点矩阵和 Nginx 保护形态。它不替代生产库核对；生产数据必须继续执行本节 SQL。

矩阵硬阈值：

| 条件 | 期望 |
|---|---:|
| 未分类端点 | 0 |
| `REQUIRE_RESOURCE + LEGACY_AUDIT` | 0 |
| 未注册 resource resolver | 0 |
| CSV 中不存在的实际 Handler | 0 |
| 实际不存在的 CSV Handler | 0 |

### 6.2 媒体节点 Hook

```sql
select id, type, status, hook_auth_enabled, hook_secret_version
  from wvp_media_server
 where hook_auth_enabled is null
    or hook_auth_enabled = false
    or hook_secret_hash is null
    or trim(hook_secret_hash) = ''
    or hook_secret_version <= 0;
```

期望：`0` 行。离线节点也必须完成密钥配置；不能因为它暂时离线就绕过 readiness。

核对未映射或缺失的 ABL networkType：

```sql
select reason_code, count(*) as occurrences
  from wvp_authz_audit
 where reason_code = 'ABL_NETWORK_TYPE_MISSING'
    or reason_code like 'ABL_NETWORK_TYPE_UNMAPPED_%'
 group by reason_code
 order by reason_code;
```

对每个 `UNMAPPED_n`，在部署配置中补充经过供应商文档确认的映射，再重走完整业务周期。`MISSING` 必须修复节点或协议适配，不能配置一个默认值掩盖。

### 6.3 云录像来源

```sql
select count(*) as unbound_cloud_records
  from wvp_cloud_record
 where source_type is null
    or source_type = 'LEGACY_UNBOUND'
    or source_id is null
    or channel_id is null;
```

enforce 前期望值：`0`。无法确认来源的旧录像应由业务负责人决定补录、隔离或删除；不得把任意通道 ID 填进去只为让数字归零。

### 6.4 LEGACY API Key

```sql
select id, user_id, app, expired_at, status
  from wvp_user_api_key
 where status = 'LEGACY'
 order by id;
```

允许进入 enforce 的两种状态：

- 结果为 `0` 行；或
- 有已审批的短兼容窗口，`legacy-api-key-enabled=true`，当前时间早于 `legacy-api-key-sunset`，并且每个调用方都有负责人、替换时间和撤销计划。

单个 Key 的 `expired_at` 已到期时，无论全局窗口是否有效都必须阻断。

### 6.5 拒绝审计

```sql
select principal_type, permission_code, resource_type, reason_code,
       count(*) as occurrences
  from wvp_authz_audit
 where create_time >= :audit_cycle_start
 group by principal_type, permission_code, resource_type, reason_code
 order by occurrences desc, reason_code;
```

逐条归类：正确拒绝、角色配置缺失、资源绑定缺失、客户端仍用旧接口、程序缺陷。只有正确拒绝可以原样保留；其余必须修复并重新收集一个受影响业务周期。禁止以扩大角色到 `ALL` 的方式消除未知拒绝。

## 7. 阶段 D：票据双轨验证和关闭长期 URL

验证所有前端播放入口先申请短期 play ticket，再拼接 FLV、WS-FLV、HLS、RTSP、RTMP 或 WebRTC 地址；分享只携带 `shareId`。快照、录像、ZIP、JT 文件下载先申请一次性 download ticket。日志 WebSocket 先申请一次性握手票据，不能在 query string 发送长期 JWT。

关闭以下开关并重新发布：

```yaml
authorization:
  allow-url-token-compatibility: false
  media:
    legacy-response-enabled: false
```

执行静态检查：

```bash
rg '\?url=|getParameter\(JwtUtils.getHeader|api_key\s*[),]|authenticatePlay\(' src web
rg 'permitAll|defaultExcludes' src/main/java/com/genersoft/iot/vmp/conf/security
rg 'mediaserver/api/downloadFile|location /record_proxy|location \^~ /mp4_record' docker/nginx
```

第一条和第三条允许命中迁移测试、数据库列名或说明文字，但不允许命中运行时长期凭证读取、公开文件 location 或旧播放放行代码。第二条的每个匿名入口都必须能在端点矩阵或安全配置说明中解释。

## 8. 阶段 E：切换 enforce

只有安全复核人确认第 6、7 节全绿后，才修改：

```yaml
authorization:
  mode: enforce
```

先灰度一个应用实例或一组明确租户/设备流量。观察窗口至少覆盖峰值流量和关键定时任务。重点监控：

- HTTP `401` 与 `403` 的路径、主体类型和原因；
- `wvp_authz_audit` 中 `DENY` 的 reason code；
- 媒体 Hook 身份失败、重放拒绝和票据失败；
- 播放、下载、分享、WebSocket 的票据申请与消费比；
- API Key owner 越权、权限 scope 越界和资源 scope 越界；
- Redis 不可用时是否 fail closed。

若出现大面积误拒绝，先把 `mode` 回到 `audit`，保留日志和数据库，不撤销已经生效的 Hook 身份认证或票据保护。修复后重新执行 readiness；不能直接在生产上增加匿名路径。

## 9. 阶段 F：清零 LEGACY API Key

逐个调用方用管理 API 轮换为 hash Key，更新调用方 Secret 后验证新 Key 的权限和资源范围，再撤销旧 Key。最终配置：

```yaml
authorization:
  legacy-api-key-enabled: false
```

最终 SQL：

```sql
select count(*) from wvp_user_api_key where status = 'LEGACY';
```

contract 前期望值必须是 `0`，不再接受短窗口例外。

## 10. 阶段 G：停机 contract

### 10.1 contract 前硬门禁

同时满足以下条件：

- 应用已稳定运行在 `enforce`；
- LEGACY API Key 为 0；
- 未绑定云录像为 0；
- 用户旧主角色到 `wvp_user_role_rel` 的漏映射为 0；
- 媒体节点 Hook 未配置为 0；
- ABL 缺失/未映射问题已清零；
- 长期 URL 双轨关闭；
- contract 前快照已恢复到隔离库并完成只读核对；
- 准备启动的新版本配置为 `authorization.legacy-role-dual-write-enabled=false`；
- 旧版本应用、定时任务和写数据库脚本全部停止。

contract 脚本自身会再次拒绝 LEGACY API Key、未绑定录像、漏回填角色关系和未知 schema 状态，但它无法读取应用配置，也无法替代停机确认。

### 10.2 执行命令

MySQL：

```bash
mysql --default-character-set=utf8mb4 --show-warnings \
  -h DB_HOST -P DB_PORT -u DB_USER -p DB_NAME \
  < 数据库/2.8.0/contract-mysql-2.8.0.sql
```

PostgreSQL：

```bash
psql --set=ON_ERROR_STOP=1 \
  --host=DB_HOST --port=DB_PORT --username=DB_USER --dbname=DB_NAME \
  --file=数据库/2.8.0/contract-postgresql-2.8.0.sql
```

KingbaseES：

```bash
ksql --set=ON_ERROR_STOP=1 \
  --host=DB_HOST --port=DB_PORT --username=DB_USER --dbname=DB_NAME \
  --file=数据库/2.8.0/contract-kingbase-2.8.0.sql
```

脚本把旧 `wvp_user_role` 主表删除，把 `wvp_user_role_rel` 基表重命名为最终 `wvp_user_role`，并创建同名于 expand 关系表的可更新视图 `wvp_user_role_rel` 供 2.8.x 新应用平滑过渡。该视图不包含旧角色主表字段，不能让 2.7.x 应用继续运行。

MySQL DDL 会隐式提交；任何执行失败都按“恢复快照”处理，不在现场拼接补救 SQL。PostgreSQL/Kingbase 脚本虽使用事务，也必须保留同等级快照。

### 10.3 contract 后只读核对

MySQL：

```sql
select table_name, table_type
  from information_schema.tables
 where table_schema = database()
   and table_name in ('wvp_user_role', 'wvp_user_role_rel',
                      'wvp_user_role_legacy_contract');
```

PostgreSQL/Kingbase：

```sql
select table_name, table_type
  from information_schema.tables
 where table_schema = current_schema()
   and table_name in ('wvp_user_role', 'wvp_user_role_rel',
                      'wvp_user_role_legacy_contract');
```

期望：

- `wvp_user_role` 是基表，列为 `user_id`、`role_id`；
- `wvp_user_role_rel` 是视图；
- `wvp_user_role_legacy_contract` 不存在；
- 两个关系对象行数相等；
- `wvp_role` 仍是角色主表；
- 新增角色/用户的自增或 sequence 大于已有最大 ID。

启动且只启动新版本，先执行只读 smoke：登录、个人信息、菜单、用户列表、角色列表、部门树、资源组树、设备/通道列表、媒体节点列表。确认无旧表字段错误后，再开放写流量和播放/下载票据验证。

## 11. 回滚决策表

| 所在阶段 | 允许的回滚 |
|---|---|
| expand 前 | 恢复应用配置即可 |
| expand 后、contract 前 | 停止新应用，确认双写一致后可回退旧应用；严重数据问题恢复 expand 前快照 |
| enforce 后、contract 前 | 先切回 `audit`；数据库仍保留 expand 结构，不需要删表 |
| contract 执行中或执行后 | 停止全部应用，恢复 contract 前快照，再启动 contract 前的新版本配置；禁止直接启动 2.7.x |

恢复后重新执行基线计数和迁移核对。任何“临时创建缺失列”“把关系表改回旧结构”都属于未经验证的前滚，不是回滚。

```

```

所有命令必须显示实际执行测试数大于 0。Kingbase 环境变量缺失时 JUnit 会显示 skipped，这不能记为 Kingbase 已通过。

## 13. 发布签字

发布记录至少包含以下结论：

```text
快照恢复演练：通过 / 不通过
expand 契约：通过 / 不通过
完整业务周期：起止时间、覆盖项、负责人
readiness：通过 / 不通过
长期 URL：关闭 / 未关闭
LEGACY API Key：数量
enforce 观察：起止时间、DENY 分类
contract 前快照：名称、校验值
contract：未执行 / 成功 / 已恢复
新版本只读 smoke：通过 / 不通过
DBA：
视频业务负责人：
安全复核人：
发布负责人：
```

任一必填项为“不通过”时，本次发布不能宣告完成。
