# WVP 2.8.0 数据库迁移运行手册

本文用于把 WVP 2.7.4 数据库扩展到 2.8.0 的身份、功能权限、部门数据范围和视频资源组模型。迁移采用 expand/contract：本阶段只增加表、列、索引和兼容关系，不删除 `wvp_user_role`，也不删除 `wvp_user.role_id`。旧应用仍能读取旧表；最终 contract 必须在 2.8.0 新版本稳定运行、readiness 门禁通过并停机后执行。

## 1. 适用范围和硬性前提

- MySQL 8.0+、PostgreSQL 14+、KingbaseES V8；H2 只用于自动化测试。
- 操作账号必须能建表、建索引、创建/修改 sequence，并能读取 `information_schema`。
- 先在生产数据副本上完整演练；Kingbase 合同测试只能连接名称明确包含 `test`、`contract`、`ci`、`scratch` 或 `disposable` 的可销毁库。
- 迁移窗口内禁止同时运行多个迁移进程。
- 迁移前记录用户、角色、API Key、云录像数量，生成可恢复快照，并实际恢复到另一数据库验证一次。
- MySQL DDL 会隐式提交。MySQL 脚本中途失败时，不应手工猜测剩余步骤，直接恢复快照后排查并重跑。

以下命令中的数据库地址、账号、目录和备份文件均为占位值，执行前必须替换。

## 2. 变更文件

| 数据库 | 新装授权结构 | 2.7.4 升级脚本 |
|---|---|---|
| MySQL | `数据库/2.8.0/初始化-mysql-2.8.0.sql` | `数据库/2.8.0/更新-mysql-2.8.0.sql` |
| PostgreSQL | `数据库/2.8.0/初始化-postgresql-2.8.0.sql` | `数据库/2.8.0/更新-postgresql-2.8.0.sql` |
| KingbaseES | `数据库/2.8.0/初始化-kingbase-2.8.0.sql` | `数据库/2.8.0/更新-kingbase-2.8.0.sql` |
| H2 | `数据库/2.8.0-h2/h2-schema.sql` | `数据库/2.8.0-h2/h2-data.sql` |

“初始化”文件只初始化 2.8.0 授权结构，业务媒体表仍以 2.7.4 完整初始化脚本为基础。新库应先执行 2.7.4 完整结构，再执行对应的 2.8.0 授权初始化文件；已有 2.7.4 数据库只执行“更新”文件。

## 3. 迁移前基线

在旧库保存以下结果。迁移后 `user_count`、`legacy_role_count`、`api_key_count` 和 `cloud_record_count` 不得减少。

```sql
select count(*) as user_count from wvp_user;
select count(*) as legacy_role_count from wvp_user_role;
select count(*) as api_key_count from wvp_user_api_key;
select count(*) as cloud_record_count from wvp_cloud_record;
select count(*) as users_with_role from wvp_user where role_id is not null;
```

保存结果示例：

```text
user_count=<填写>
legacy_role_count=<填写>
api_key_count=<填写>
cloud_record_count=<填写>
users_with_role=<填写>
```

如果旧库已经存在孤立角色引用，先停止迁移并修复：

```sql
select u.id, u.username, u.role_id
  from wvp_user u
  left join wvp_user_role r on r.id = u.role_id
 where u.role_id is not null
   and r.id is null;
```

期望：0 行。失败动作：恢复或补齐对应 `wvp_user_role` 数据，不得把用户静默改成管理员角色。

## 4. 快照及恢复演练

### 4.1 MySQL

```bash
mysqldump --single-transaction --routines --triggers --events \
  -h DB_HOST -P 3306 -u DB_USER -p wvp > wvp-2.7.4-pre-expand.sql

mysql -h RESTORE_HOST -P 3306 -u RESTORE_USER -p \
  -e 'drop database if exists wvp_restore; create database wvp_restore character set utf8mb4;'
mysql -h RESTORE_HOST -P 3306 -u RESTORE_USER -p wvp_restore \
  < wvp-2.7.4-pre-expand.sql
```

### 4.2 PostgreSQL

```bash
pg_dump -Fc -h DB_HOST -p 5432 -U DB_USER -d wvp \
  -f wvp-2.7.4-pre-expand.dump

createdb -h RESTORE_HOST -p 5432 -U RESTORE_USER wvp_restore
pg_restore --exit-on-error --clean --if-exists \
  -h RESTORE_HOST -p 5432 -U RESTORE_USER -d wvp_restore \
  wvp-2.7.4-pre-expand.dump
```

### 4.3 KingbaseES

Kingbase 工具通常位于安装目录的 `Server/bin`，实际名称和参数以部署版本为准。

```bash
sys_dump -Fc -h DB_HOST -p 54321 -U DB_USER -d wvp \
  -f wvp-2.7.4-pre-expand.dump

sys_restore --exit-on-error --clean --if-exists \
  -h RESTORE_HOST -p 54321 -U RESTORE_USER -d wvp_restore \
  wvp-2.7.4-pre-expand.dump
```

恢复库必须重新执行第 3 节五条基线 SQL，结果与源库一致。任何一项不一致，都不能进入迁移。

## 5. 执行 expand

迁移前停止 2.7.4 应用写入，确认无后台任务继续更新用户、API Key 或云录像元数据。

### 5.1 MySQL 2.7.4 升级

```bash
mysql --default-character-set=utf8mb4 --show-warnings \
  -h DB_HOST -P 3306 -u DB_USER -p wvp \
  < 数据库/2.8.0/更新-mysql-2.8.0.sql
```

### 5.2 PostgreSQL 2.7.4 升级

```bash
psql -v ON_ERROR_STOP=1 -h DB_HOST -p 5432 -U DB_USER -d wvp \
  -f 数据库/2.8.0/更新-postgresql-2.8.0.sql
```

### 5.3 KingbaseES 2.7.4 升级

```bash
ksql -v ON_ERROR_STOP=1 -h DB_HOST -p 54321 -U DB_USER -d wvp \
  -f 数据库/2.8.0/更新-kingbase-2.8.0.sql
```

脚本均按可重复执行设计。发生连接中断时，先判断数据库类型：PostgreSQL/Kingbase 脚本在事务内执行，可确认事务是否回滚后重跑；MySQL 直接恢复快照，再完整重跑。

## 6. expand 后核对 SQL

每条检查都要保存 SQL、结果、执行时间和执行人。以下“期望值”不满足时不得启动 2.8.0。

### 6.1 数量与兼容关系

```sql
select count(*) as user_count from wvp_user;
select count(*) as users_with_role from wvp_user where role_id is not null;
select count(*) as migrated_role_rel
  from wvp_user u
  join wvp_user_role_rel urr
    on urr.user_id = u.id and urr.role_id = u.role_id
 where u.role_id is not null;
select count(distinct user_id) as users_in_new_rel from wvp_user_role_rel;
```

期望：`user_count` 等于迁移前；`users_with_role = migrated_role_rel`。`users_in_new_rel` 可以大于 `users_with_role`，因为 2.8.0 支持一个用户多个角色。

失败动作：停止启动；检查孤立旧角色和迁移日志。不得用删除用户或强制绑定超级管理员来“对齐”数量。

旧应用兼容读取：

```sql
select u.id, u.username, u.role_id, r.name, r.authority
  from wvp_user u
  left join wvp_user_role r on r.id = u.role_id
 order by u.id;

select id, user_id, app, api_key, expired_at, remark, enable
  from wvp_user_api_key
 order by id;
```

期望：两条 SQL 均可执行，旧列仍存在。失败动作：恢复快照；expand 阶段禁止删除或重命名旧表列。

### 6.2 部门和视频资源组闭包

```sql
select count(*) as root_dept_closure
  from wvp_dept d
  join wvp_dept_closure c
    on c.ancestor_id = d.id and c.descendant_id = d.id and c.depth = 0
 where d.dept_code = 'ROOT' and d.parent_id = 0;

select count(*) as root_video_closure
  from wvp_resource_group g
  join wvp_resource_group_closure c
    on c.ancestor_id = g.id and c.descendant_id = g.id and c.depth = 0
 where g.group_code = 'ROOT_VIDEO' and g.parent_id = 0;

select count(*) as groups_without_self_closure
  from wvp_resource_group g
 where not exists (
     select 1 from wvp_resource_group_closure c
      where c.ancestor_id = g.id
        and c.descendant_id = g.id
        and c.depth = 0
 );
```

期望：前两项均为 1，第三项为 0。失败动作：停止启动并恢复快照，检查根数据是否被手工占用了固定 ID 或唯一编码。

### 6.3 资源、录像来源与超级管理员

```sql
select count(*) as orphan_resource_items
  from wvp_resource_group_item rgi
 where not exists (
     select 1 from wvp_resource_group rg where rg.id = rgi.group_id
 );

select count(*) as invalid_unbound_cloud_records
  from wvp_cloud_record
 where channel_id is null
   and source_type <> 'LEGACY_UNBOUND';

select count(*) as super_admin_count
  from wvp_role
 where role_key = 'super_admin'
   and system_role = 1
   and dept_data_scope = 'ALL'
   and video_scope_type = 'ALL';
```

期望：依次为 0、0、1。失败动作：孤立资源或录像来源异常时停止启动；超级管理员异常时恢复快照，禁止临时把普通角色扩成 `ALL`。

### 6.4 API Key 状态和范围

```sql
select count(*) as api_key_count from wvp_user_api_key;
select count(*) as legacy_api_key_count
  from wvp_user_api_key where status = 'LEGACY';
select count(*) as active_key_without_hash
  from wvp_user_api_key
 where status = 'ACTIVE'
   and (key_hash is null or key_hash = '');
select count(*) as orphan_permission_scope
  from wvp_api_key_permission s
 where not exists (select 1 from wvp_user_api_key k where k.id = s.api_key_id)
    or not exists (select 1 from wvp_menu m where m.id = s.menu_id);
select count(*) as orphan_resource_scope
  from wvp_api_key_resource_group s
 where not exists (select 1 from wvp_user_api_key k where k.id = s.api_key_id)
    or not exists (select 1 from wvp_resource_group g where g.id = s.resource_group_id);
```

期望：`api_key_count` 等于迁移前；`legacy_api_key_count` 等于迁移前仍在使用明文的 Key 数量；其余三项为 0。LEGACY 数量在 expand 后允许非零，但必须在 contract 前归零或进入批准的短兼容期。

失败动作：数量减少立即恢复快照；ACTIVE Key 无 hash 或 scope 孤立时停止启动，修复迁移脚本后在恢复库重演。

### 6.5 索引与唯一约束

必须确认以下索引列顺序存在：

```text
wvp_user                       (dept_id, status, deleted)
wvp_user_role_rel              (role_id, user_id)
wvp_resource_group_closure     (descendant_id, ancestor_id)
wvp_resource_group_item        (resource_type, resource_id)
wvp_role_resource_group        (resource_group_id, role_id)
wvp_user_api_key               (user_id, status)
wvp_api_key_permission         (menu_id, api_key_id)
wvp_api_key_resource_group     (resource_group_id, api_key_id)
wvp_cloud_record               (channel_id, start_time)
```

同时确认以下组合唯一：

```text
wvp_user_role_rel              (user_id, role_id)
wvp_resource_group_item        (group_id, resource_type, resource_id)
wvp_user_api_key               (key_hash)
wvp_api_key_permission         (api_key_id, menu_id)
wvp_api_key_resource_group     (api_key_id, resource_group_id)
```

失败动作：不要在高峰期临时补索引；回到演练环境修正脚本，评估锁表时间后重新安排窗口。

### 6.6 sequence/自增

数据库契约测试会对用户、旧角色、API Key、新角色、部门、资源组和菜单执行一次默认 ID 插入，并要求新 ID 大于迁移前最大值。生产核对至少检查下列对象。

PostgreSQL：

```sql
select 'wvp_user' as table_name, max(id) as max_id,
       last_value as sequence_value from wvp_user, wvp_user_id_seq group by last_value
union all
select 'wvp_user_role', max(id), last_value
  from wvp_user_role, wvp_user_role_id_seq group by last_value
union all
select 'wvp_user_api_key', max(id), last_value
  from wvp_user_api_key, wvp_user_api_key_id_seq group by last_value;
```

KingbaseES 使用同名 sequence 执行等价查询。期望：`sequence_value >= max_id`。失败动作：停机后执行对应脚本中的 `setval`，再用可回滚事务插入并回滚一条测试数据。

MySQL：

```sql
select table_name, auto_increment
  from information_schema.tables
 where table_schema = database()
   and table_name in (
       'wvp_user', 'wvp_user_role', 'wvp_user_api_key',
       'wvp_role', 'wvp_dept', 'wvp_resource_group', 'wvp_menu'
   );
```

期望：每个非空表的 `auto_increment > max(id)`。失败动作：停机后使用 `alter table <table> auto_increment = <max_id + 1>`，随后重新核对。

## 7. 自动化数据库契约

MySQL、PostgreSQL 和 H2：

```bash
mvn -Pdb-contract \
  -Dtest=RbacMySqlMigrationTest,RbacPostgreSqlMigrationTest,MediaAuthorizationSchemaContractTest \
  test
```

该命令当前必须满足：4 项测试通过，0 失败、0 错误、0 跳过。它会启动临时 MySQL/PostgreSQL 容器，验证 fresh init、2.7.4→2.8.0 expand、Docker 初始化链、contract 前置拒绝、最终表名和 contract 幂等性，并在 JVM 退出时清理容器；不会启动 WVP 业务服务。

KingbaseES：

```bash
export WVP_KINGBASE_JDBC_URL='jdbc:kingbase8://HOST:PORT/wvp_contract_test'
export WVP_KINGBASE_USERNAME='contract_user'
export WVP_KINGBASE_PASSWORD='***'
mvn -Pkingbase-contract -Dtest=RbacKingbaseMigrationTest test
```

三个环境变量缺失时用例会明确跳过；正式发布证据不得把“跳过”记为通过。URL 不含可销毁测试库标识时测试会在执行任何建表语句前失败。

## 8. expand 回退

### 新版本尚未写入数据

1. 停止 2.8.0 应用。
2. 恢复迁移前快照。
3. 执行第 3 节基线 SQL，确认数量一致。
4. 启动 2.7.4，只执行只读 smoke；确认后再恢复写入。

### 新版本已经写入 2.8.0 数据

expand 保留旧表，因此短时间内可以回退应用二进制，但 2.7.4 不认识多角色、部门范围、视频资源组和新 API Key scope。必须先冻结写入并评估数据：

- 不删除新表来迁就旧应用；
- 不把多角色关系任意压缩到一个 `role_id`；
- 不把已轮换的 API Key 还原成明文；
- 需要永久回退时，以迁移前快照为基础，按业务时间点补录允许回放的数据。

## 9. contract 前置条件

仅当以下条件全部满足时，才进入 `2.8.0-authorization-rollout.md` 的停机 contract：

- `authorization.mode=enforce` 已运行一个观察窗口；
- readiness 测试通过；
- 端点和视频资源授权矩阵无未分类项；
- 长期媒体 URL 双轨已关闭；
- 媒体节点 Hook secret 全部配置并验证；
- LEGACY API Key 已清零；短兼容期只允许进入 enforce 观察，不允许进入 contract；
- 未绑定云录像已完成处置；
- 最新快照已在独立恢复库验证。

停机前还必须把新版本配置改为 `authorization.legacy-role-dual-write-enabled=false`。随后按数据库执行独立脚本：

```text
数据库/2.8.0/contract-mysql-2.8.0.sql
数据库/2.8.0/contract-postgresql-2.8.0.sql
数据库/2.8.0/contract-kingbase-2.8.0.sql
```

contract 会删除旧角色主表并把 `wvp_user_role_rel` 基表改名为最终 `wvp_user_role`，同时保留一个可更新的 `wvp_user_role_rel` 过渡视图供 2.8.x 新应用使用。该视图不是旧角色主表，2.7.4 仍不能运行。脚本失败时只能恢复 contract 前快照，禁止混合新旧表名继续运行。逐步命令、只读 smoke 和回滚决策见 [2.8.0 授权灰度操作手册](2.8.0-authorization-rollout.md)。
